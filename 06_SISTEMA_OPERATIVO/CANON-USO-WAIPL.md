# CANON en el Lab — para qué sirve (1 página)

CANON no es un nodo. No es Aether. No es Hermes. Es la forma operativa del Principio 12: **no cierres un trabajo hasta que el bucle haya pasado por todas las capas**.

Lo que ya os ha pasado, con el nombre de la capa:

| Capa CANON | En el Lab | Ejemplo de hoy |
|---|---|---|
| Interfaz | El Soberano no es el cable | Issue #13 en vez de copiar markdown |
| Orquestador | Uno solo por trabajo | Hermes dirige; AutoClaw pica; Z pica Positrón. No tres planes |
| Doctrina | N3 sellado + glosario | `fix_hermes_tasks.ps1` rechazado; Aether-Hermes derogado |
| Subagentes | Superficies sin solape | AutoClaw = disco Hermes. Z = Next de Positrón. Grok = spec/GitHub |
| Runtime | El cuerpo | 8787, una tarea, venv. No el informe |
| Verificación | HTTP 200 no es el producto | Hidratación de Z; bytes 8336 vs 8626 del spec |
| Parada | STOP del N3 | AutoClaw sin token → paró. Correcto |

## Uso 1 (el que importa ahora) — lista de cierre

Todo informe «completo» de AutoClaw, Z o Hermes lleva 7 casillas. Si falta una, no está cerrado:

1. **Quién orquesta** (un nombre).
2. **Doctrina** (qué N3 / spec).
3. **Superficie** (qué disco / repo; qué no se toca).
4. **Runtime** (proceso o archivo real).
5. **Verificación** (comando + resultado, no narrativa).
6. **Parada** (qué habría abortado).
7. **Qué no es** (no 24/7, no ONLINE, no DELIVERED).

Eso es CANON diluido. No hace falta el visor para usarlo mañana.

## Uso 2 — dashboard Hermes (después, otro N3)

Sustituir el chip «Online» por el estado del bucle del trabajo en curso: doctrina cargada / runtime up / verificación / parado. Una fila, no un folleto.

## Qué no es

No se fusiona con Hermes. No entra al Núcleo. No se mergea el visor al repo del Lab sin grant. El visor que descargaste es la edición larga; esta página es la masticada.
